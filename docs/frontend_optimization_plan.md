## 一、现状的四个痛点

1. **77 项检查不可检索。** 清单是 5 个分组卡片平铺（`renderChecks`），只有 5 个固定预设（全选/结构/元数据/排版/清空）。想"只跑结构 + 缺封面 + 重复 ISBN"只能手工在几十行里点，选完没有名字、下次还得重来。
2. **检查项文案是英文。** 名称与 tooltip 直接来自上游 `menus.py`，而 `qc/__init__.py` 装的是 identity gettext、宿主也不往 `builtins` 注入 `_`，于是中文界面里混着 "Check title sort"。报告筛选下拉显示的更原始——裸 key（`check_epub_css_margins (12)`），`skipped` 提示同理。这是"看起来不像原生工具"的最大来源。
3. **报告只有"按书罗列"一个视角。** 服务端已经返回 `summary`/`per_check`，但前端只拿它填了一个下拉框；没有"按检查项看哪个最脏"，也没有"点开一本书一次修完"的聚焦视图。整库体检最典型的用法（先看哪类问题最多，再决定修哪批书）现在要人肉统计。
4. **请求与状态治理偏弱。** 轮询是 `setInterval`（不等待上一次响应，慢响应可能覆盖新状态）；筛选/翻页请求没有取消机制，快速切换会出现旧响应写进表格；`renderChecks/renderReport/renderRows/renderPicked` 各自手动调用，语言切换时要记得重画四处（`i18n.onChange` 里就得列 4 个调用），漏一个就出现"半翻译"界面。

## 三、P1：报告体验（目标 1.2）

6. **新增 `/summary`（唯一建议的后端改动）**
   读同一个 `report.json`，只回汇总：`per_check` 计数、严重度分布、受影响书籍数、每项耗时（若 report 里记录）。
   用途是支撑下面的"按检查项"视图。成本约 40 行，与 `/report` 共用读文件逻辑，风险低。
   （备选：不新增路由，`/report` 支持 `fields=summary` 只回汇总。二选一即可。）

7. **报告页签化：`按书` / `按检查项`**
   - 按书：保留现有展开明细。
   - 按检查项：一张表（检查项 / 命中书数 / 严重度 / 前 3 本书），点击某行 → 切到"按书"并带上该检查项筛选。
   这样"体检报告"从一堆行变成"先看哪个检查项最脏，再下钻到书"。

8. **单本聚焦**：点书名在页内弹出该书全部问题与逐条日志（书名旁边保留"去书籍详情"链接）。整库体检里"修完这本再下一本"是最常见的动作路径。

9. **导出增强**：导出前显示将导出多少行，可选"仅当前筛选/全部"；补一个"导出 JSON"（直接落服务端报告，避免 CSV 把 `detail` 用 ` | ` 拼平后丢结构）；超过 20000 行的截断必须在界面上说出来（现在静默截断）。

10. **空态/错误态**：区分"这次全干净"与"该筛选下没有"；`errors` 从脚注（现在只显示条数）变成可展开面板，能逐条看到 `check/book_id/error`。

## 四、P2：打磨（1.3+）

11. **列表窗口化/分页渲染**：`pageSize` 调大或"展开全部"时，几千行的 DOM 会卡；给 `#report-body` 做简单的窗口化（或保持 50/页但允许"每页 200"并只渲染可视区）。
12. **键盘与无障碍**：`/` 聚焦检索、清单项空格切换、表格行 `Enter` 展开；进度区 `aria-live`、展开行 `aria-expanded`；焦点样式（现在依赖浏览器默认）。
13. **移动端**：< 640px 时报告表格改卡片式（一行一张小卡，书名/格式/问题竖排），进度区折两行；检查项清单已经是单列 ✓。
14. **深色模式变量化**：徽章/告警的 5 处硬编码浅色（`#fde7e7` `#fdf0e2` `#e6f2fb` …）现在是靠 `body[data-theme="dark"]` 逐条覆写；改成成对的 CSS 变量（如 `--mb-color-error-bg`），以后新增颜色不会再漏。
15. **渲染集中化（可选重构）**：把 `bind()` 的事件回调统一成"改 state → 调一次 `render()`"，替掉现在"语言切换要手动重画 checks/report/scope 四处"的模式。不引框架，只是把渲染入口收成一个，减少漏画。

## 五、明确不做

- **不引 Vue/React/构建链**：宿主 iframe 里就是静态页，无构建、零依赖是这个工具的优点（装机不需要 npm，也不会因宿主前端版本变化而崩）。
- **不做流式增量报告**：宿主任务进度只带计数，把报告分片下发要改后端契约；先把汇总视图做好，收益更大。
- **不动检查项的 key 与分组**：那是 GPL 移植的一部分，改了会让与上游 `menus.py` 的对比变难。
